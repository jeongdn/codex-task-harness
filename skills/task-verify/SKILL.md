# 검증

1. 전체 테스트(`python3 -m unittest discover -s tests -v`)를 실행하고 명령과 결과(통과·실패 수)를 VERIFY.md에 적는다.
2. 성공 기준(M)은 실제 데이터로 직접 실행해 숫자를 확인한다. 테스트 통과만 믿지 않는다.
3. AGREEMENT.md의 항목마다 판정한다: 충족 / 부분 / 미충족 / 확인 불가. 근거로 파일·함수 이름이나 명령 출력을 붙인다.
4. 담당자가 다음에 쓰는 상황을 흉내 내 한 번 더 돌린다. 원본은 건드리지 않고 임시 폴더에서 한다.
   - 예: 다음 주 파일(이번 파일을 복사해 이름만 바꾼 것)을 넣기, 새 문서 추가, 다른 날짜의 로그.
   - 코드 수정 없이 명령 한 줄로 돌아가는지 본다.
   - 코드에서 이번 데이터 전용 값(파일 이름, 주차, 날짜, 예상 건수)을 찾아(grep) 목록으로 보고한다.
5. 결과물의 첫 줄(요약 첫 줄, 화면 맨 위)이 담당자가 물은 질문에 바로 답하는지(무엇이, 얼마나) 본다.
6. 경계 입력을 3가지 이상 시험한다: 빈 값, 형식이 다른 값, 중복, 아주 큰 값, 없는 키 등. 결과를 적고 추가할 테스트를 제안한다.
7. 금지(D)와 제약(C) 위반을 따로 확인한다: 원본 파일 수정, 외부 호출, 설치가 필요한 패키지, 하지 말라고 한 기능.
8. 위험과 한계, 다음에 검증할 것을 적는다.
9. 코드는 고치지 않는다. 고칠 것은 우선순위와 예상 시간을 붙여 보고하고 멈춘다. 사용자가 고치기로 하면 task-build A 형식으로 그 부분의 설계를 보여 주고 승인받은 뒤 고친다.
