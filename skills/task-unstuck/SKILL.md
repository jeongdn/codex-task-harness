# 막혔을 때

1. 코드를 더 고치지 않는다. 먼저 상태를 모은다:
   `python3 ~/.agents/skills/task-unstuck/scripts/diagnose.py`
   (git 최근 커밋과 바뀐 파일, 열린 포트와 바인딩 주소, 3000번 응답, 서버 프로세스, 최근 수정 파일, 설치된 패키지)
2. 마지막으로 실패한 명령을 한 번만 다시 실행해 오류 원문(마지막 20줄)을 확보한다.
3. 문제를 한 문장으로 쓴다: 무엇을 했을 때, 무엇이 기대와 다르게, 어떤 오류로.
4. 원인 후보를 가능성 높은 순서로 3개 이내로 적고, 각각 확인 방법을 한 줄씩 붙인다.
5. 선택지를 2~3개 보여 준다. 각각 예상 시간과 위험을 붙인다. 그중 하나는 항상 "마지막 정상 커밋(테스트 통과)으로 되돌리고 다른 방법으로"다. 되돌리기는 파일 단위나 `git stash`로 제안하고, 사용자가 고른 뒤에만 실행한다.
6. 웹 미리보기 문제면 이 순서로 본다.
   - 서버 프로세스가 떠 있나 (끝나지 않는 서버는 사용자가 다른 터미널 탭에서 띄우게 한다)
   - 0.0.0.0에 바인딩됐나 (127.0.0.1이면 미리보기가 못 본다)
   - 포트가 3000인가 (아니면 미리보기 PORT 칸을 그 번호로)
   - `curl -s localhost:3000`이 응답하나, 경로가 맞나
   - Vite·Next 같은 개발 서버면 외부 호스트 허용 설정
7. 패키지가 없어서 막히면 설치보다 표준 라이브러리 대안을 먼저 제안한다. 설치가 꼭 필요하면 이유와 명령을 보여 주고 승인을 받는다.
8. 무엇이 안 됐고 왜 방법을 바꿨는지 DECISIONS.md에 한 줄 남긴다. 확인 문제 ②번(AI 제안 확인·수정) 재료다.
