# 구현 계획

1. AGREEMENT.md와 NOTES.md를 읽는다. 남은 시간을 모르면 사용자에게 묻는다.
2. 전체 구조를 한 줄 그림으로 만든다(입력 → 주요 처리 → 출력/화면). 채팅에 보여 주고 DESIGN.md의 '전체 구조'에 적는다.
3. 단계를 4~7개로 나눈다.
   - 1단계: 데이터 읽기·정리와 그 테스트 (NOTES.md에 적힌 이상한 값 처리 포함)
   - 2단계 안에: 담당자의 성공 기준(M)을 확인하는 테스트
   - 마지막 단계: 결과 형태(화면, 리포트, CLI 출력) 다듬기
4. 단계마다 완료 조건을 실행 가능한 명령으로 적는다. 예: `python3 -m unittest discover -s tests -v`. 그리고 '끝나면 사용자가 직접 볼 수 있는 것'을 한 줄 적는다(예: 미리보기에서 노선 목록이 보임).
5. 예상 시간에는 단계마다 설계 승인과 이해 확인 몫으로 약 5분을 넣는다. 단계별 예상 시간의 합이 남은 시간의 70%를 넘지 않게 한다. 나머지는 검증, 제출 문서, 설명 연습 몫이다.
6. '시간이 모자라면 버릴 순서'를 적는다. 꾸미기와 부가 기능부터 버리고, 성공 기준과 금지 사항은 끝까지 지킨다.
7. 기술 선택은 AGREEMENT.md의 제약(설치 가능 여부, 외부 전송 금지 등)을 먼저 따르고, 선택 이유를 DECISIONS.md에 한 줄 남긴다. 함수 단위 설계는 각 단계를 시작할 때 task-build로 따로 승인받는다.
8. 계획만 쓰고 코드는 쓰지 않는다. 채팅에는 전체 구조 그림과 단계 표만 보여 주고 사용자 확인을 기다린다.
