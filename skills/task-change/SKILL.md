# 요구가 바뀌었을 때

입력: 담당자의 새 말(사용자가 붙여 넣은 대화).

1. INTERVIEW.md 표 끝에 다음 번호로 덧붙인다(기존 행은 그대로 둔다). 이전 답과 다르면 '정정'이라고 쓰고 이전 번호를 붙인다. 담당자 표현은 줄이지 않는다.
2. 영향 범위를 표로 보여 준다: 바뀌는 요구(AGREEMENT 항목), 바뀌는 함수·파일, 깨질 테스트, 새로 필요한 테스트, 예상 시간.
3. 남은 시간과 비교해 선택지를 준다: 지금 반영 / 일부만 반영 / 반영하지 않고 한계로 적기. 성공 기준(M)이 바뀌었으면 그것부터 한다. 그리고 멈춰서 사용자가 고르기를 기다린다.
4. 사용자가 고르면 AGREEMENT.md를 고치고(바뀐 줄 끝에 "(변경: 인터뷰 번호)"), PLAN.md를 고치고, 사용자가 말한 이유를 DECISIONS.md에 한 줄 남긴다.
5. 반영하기로 했으면 코드를 고치기 전에 바뀌는 부분의 설계를 task-build A 형식으로 보여 주고 승인받는다. 바뀐 기준은 테스트로 먼저 만든다.
6. 담당자에게 보낼 짧은 확인 메시지(바뀐 점 2~3줄 + "이렇게 바꾸면 될까요?")를 만든다.
