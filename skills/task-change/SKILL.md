# 요구가 바뀌었을 때

입력: 담당자의 새 말(사용자가 붙여 넣은 대화).

1. INTERVIEW.md에 새 행으로 추가한다. 이전 답과 다르면 '정정'이라고 쓰고 이전 번호를 붙인다. 담당자 표현은 줄이지 않는다.
2. AGREEMENT.md에서 바뀌는 항목을 고치고, 바뀐 줄 끝에 (변경: 인터뷰 번호)를 붙인다.
3. 영향 범위를 표로 보여 준다: 바뀌는 함수·파일, 깨질 테스트, 새로 필요한 테스트, 예상 시간.
4. 남은 시간과 비교해 선택지를 준다: 지금 반영 / 일부만 반영 / 반영하지 않고 한계로 적기. 성공 기준(M)이 바뀌었으면 그것부터 한다.
5. PLAN.md를 고치고, 판단과 이유를 DECISIONS.md에 한 줄 남긴다.
6. 코드는 사용자가 고른 뒤에 고친다. 고칠 때는 바뀐 기준을 테스트로 먼저 만든다.
7. 담당자에게 보낼 짧은 확인 메시지(바뀐 점 2~3줄 + "이렇게 바꾸면 될까요?")를 만든다.
