# 설명 연습 (확인 문제 대비)

실제 확인 문제는 고정된 제출물과 AI와 나눈 프롬프트로 만들어지고, 문항당 몇 분 안에 AI 없이 직접 쓴다. 이 스킬은 그 연습이다. 답을 대신 써 주지 않는다.

1. 제출 문서, DESIGN.md, DECISIONS.md, AGREEMENT.md, 핵심 코드 파일을 읽는다.
2. 질문을 준비한다. 기본 6개, 사용자가 "짧게"라고 하거나 남은 시간이 15분보다 적으면 앞의 3개만. 실제 함수·파일·기준값 이름을 넣는다. 1~5번은 실제 본시험(10/31)에서 나온 유형이다.
   1. 입력 데이터가 어떤 모듈(파일·함수)을 거쳐 화면·출력까지 가나, 잘못된 입력은 어디서 막나
   2. 왜 완전탐색(또는 가장 단순한 방법)이 아니라 이 알고리즘·기준을 골랐나, 한계와 확인 방법
   3. AI가 만든 코드를 그대로 믿지 않으려고 무엇을 했나, 고친 제안은 무엇이고 왜 (DECISIONS.md의 사용자 결정에서 고른다)
   4. 데이터의 주인은 누구이고, 누가 보고 고칠 수 있나, 무엇을 저장하지 않았나
   5. 역할(예: 운영자와 사용자)의 로그인과 권한 경계를 어떻게 나눴나, 서버에서 어디서 막나 (역할이 하나면 특정 입력·경계값에서 무슨 일이 생기나로 바꾼다)
   6. 시간이 더 있으면 무엇을 어떤 기준으로 검증·개선하나
   2번부터 6번 중 하나에는 실제와 다른 전제를 슬쩍 섞는다(없는 기능, 다른 기준값, 쓰지 않은 방법). 어느 것인지는 말하지 않는다.
3. 한 번에 한 질문만 낸다. 사용자가 답하면:
   - 맞은 점, 틀리거나 빠진 점을 코드 근거(파일:함수)와 함께 2~3줄로 알려 준다.
   - 더 나은 답의 골격을 3줄로 준다: 무엇을 → 어떻게 확인했나(명령·숫자) → 왜 / 한계.
   - 전제가 틀린 질문을 그대로 받아들였으면 그 점을 짚는다.
4. 끝나면 사용자가 약했던 부분 2개와, 제출 전에 다시 읽을 파일·함수를 알려 준다.
5. 코드나 문서는 고치지 않는다. 고칠 점이 보이면 목록으로만 알려 준다.
