# 비상 마감

목표: 남은 시간 안에 "돌아가는 것 + 정직한 설명"을 제출한다. 새 기능은 만들지 않는다.

1. 남은 시간을 확인한다. 모르면 사용자에게 묻는다.
2. 지금 상태를 판정한다: 전체 테스트(`python3 -m unittest discover -s tests -v`)와 실행 명령(제출 문서에 있으면 그것, 없으면 PLAN.md·DESIGN.md에 적힌 것)을 한 번씩 돌린다.
3. 깨져 있으면 `git log --oneline`에서 메시지에 "(테스트 n/n 통과)"가 붙은 마지막 커밋을 찾고, 그 뒤 바뀐 파일을 보여 준다.
   - 되돌릴 파일은 사용자에게 묻고, 답을 받은 뒤에만 되돌린다.
   - 먼저 지금 상태를 `[임시] 되돌리기 전` 커밋으로 남기고, `git restore --source <그 커밋> -- <파일>`로 파일 단위로만 되돌린다. `git stash`, `git reset --hard`, `git clean`은 쓰지 않는다(숨겨 둔 작업은 제출물에서 빠진다).
4. PLAN.md의 '시간이 모자라면 버릴 순서'대로 남은 단계를 자른다. 성공 기준(M)과 금지(D)는 남긴다. 버린 것을 표로 보여 주고 사용자 확인을 받는다.
5. 남은 시간이 20분 이상이면 성공 기준 하나만 마무리한다. 이때도 고칠 부분의 설계를 task-build A 형식으로 짧게 보여 주고 승인받는다. 20분보다 적으면 코드는 멈춘다.
6. 제출 문서를 쓴다($task-submit과 같은 골격, 파일명은 task-submit 1번 규칙). 못 한 것은 "하지 못함: 이유 / 다음에 할 방법"으로 정직하게 적는다.
7. 바꾼 파일만 커밋하고, 채팅에 "제출 전 30초 점검"을 보여 준다: 실행 명령 한 줄, 성공 기준 결과, 버린 것, 확인 문제에서 말할 핵심 3가지.
