# DESIGN.md

승인한 설계를 남긴다(task-plan이 아래 다섯 칸의 초안을, task-build가 단계별 설계를 채운다). 확인 문제는 이 다섯 가지를 자주 묻는다. 제출 전에 이 파일부터 읽는다.

## 꼭 설명할 수 있어야 하는 것

### 1. 모듈과 데이터 흐름
입력 → 모듈(파일·함수) → 출력/화면, 모듈마다 책임 한 줄, 잘못된 입력을 어디서 막는지

### 2. 알고리즘 선택
쓴 방법 / 완전탐색(또는 가장 단순한 방법) 대신 고른 이유(데이터 크기와 시간) / 놓치는 것(한계) / 결과가 괜찮은지 확인한 방법

### 3. 데이터 소유와 보관
데이터의 주인 / 누가 보고 고칠 수 있나 / 어디에 저장하고 무엇은 저장하지 않나(개인정보 최소화) / 원본은 수정하지 않음

### 4. 역할과 권한 경계 (사용자가 여럿일 때)
역할별 할 수 있는 일 / 로그인 방식 / 권한을 서버에서 검사하는 곳(화면에서 숨기는 것만으로는 막지 못함)

### 5. AI 결과 검증
무엇으로 확인했나(테스트, 손 계산, 경계값, 직접 실행) / 내가 고친 AI 제안과 이유
